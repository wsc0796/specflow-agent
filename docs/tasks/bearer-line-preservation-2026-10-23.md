# Bearer 脱敏与源码行号保持

状态：用户于 2026-10-23 批准本次限定修复。
基线：`773cab9e24bdcf4f990afe7897dcdf7459c4e372`。
分支：`codex/bearer-line-preservation`。

## 已观察到的故障

外置取证原型发现搜索行号与读取内容不一致。Bearer 正则误匹配
`HTTPBearer` 的后缀、换行和下一行的 `from`，JSON 整串脱敏将 33 行源码
变成 32 行。原型随后标错引用位置，并可能索引不存在的末行。
原搜索摘录仍使用原始行号，不能将该故障扩大为全部旧引用均错误。

## 授权范围

- `src/specflow/tools/sanitization.py`：要求独立的 Bearer 单词，替换凭据时
  保留原空白分隔符，包括 LF/CRLF。
- `tests/test_repository_tools.py`：实际读文件、搜索及最终 DLP 链路回归，
  与真实凭据格式继续脱敏的正向样例配对。
- `tests/test_tool_framework.py`：嵌套工具结果 JSON 的布局与脱敏回归。
- 本任务及对应完成报告。

真实模型调用为 0；不改变取证策略、模型配置、依赖或目标仓库。
不重跑整个原型追求覆盖率，不绕过最终 DLP 或削弱敏感键脱敏。
更广泛的脱敏或源码位置映射修改须另行界定范围。

## 验收条件

1. LF/CRLF 源码中的 `HTTPBearer` 经过 read_file、ToolResult 规范化与
   最终 DLP 后保持原文；搜索行号能定位相同源码行，包括末行。
2. 独立 Bearer 凭据在大小写变化、空格、制表符和跨行分隔时继续隐藏，
   分隔符的行结构保持。
3. 嵌套结果字典/列表保留类型和普通值，敏感键继续隐藏；重复最终扫描稳定。
4. 聚焦回归在旧实现上失败、修复后通过；完成全量离线 pytest 与 Ruff 后提交。
5. 保留旧失败与原型证据。结论限定为源码证据可靠性修复，不宣称模型回答质量提升。
