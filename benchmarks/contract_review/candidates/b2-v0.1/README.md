三个版本概念分开：API v2是业务版本；ruleset_version是正式规则集版本；review.version是HTTP更新的CAS版本。
输入ID、jobID和adoptionID由宿主生成，不自行编造。

文件阅读顺序：
1. cases.json：每例材料、目标、正式发布／审查／答案步骤。steps是编排草稿，不是可直接发送的HTTP正文。
2. oracles.json：独立必要结论、禁止结论、允许未知与取证要求；它不进入模型输入。
3. human-scripts.json：问题真的出现且允许对应答案后，才解析真实ID并提交；不预填到初始请求。
4. demo-abc.json：A/B/C串联演示，身份待定、不加入五例分母、不代替独立case验收。
5. manifest.json：原身份、候选范围与待批准配置。原24例manifest及六例正文保持原样。
